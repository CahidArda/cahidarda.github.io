It is natural to think that a true statement just needs a clever enough proof. In 1931 Kurt
Gödel showed otherwise. In any consistent set of rules strong enough to do arithmetic, some true
statements cannot be proved with those rules. These are **Gödel's incompleteness theorems**.

## A puzzle you can't finish

Douglas Hofstadter opens _Gödel, Escher, Bach_ (1979) with a game. You start with the string MI
and four rules for making new strings. Can you make MU?

  <MiuPlayground client:visible />
</div>

You can't. Hofstadter's answer (chapter IX) is to stop playing and count: "we can show that the
I-count can never be any multiple of 3". Rule II doubles the count and rule III takes away 3, so
from 1 the count is never divisible by 3:

$$
\#I \bmod 3 \in \{1, 2\} \qquad \text{but MU has } \#I = 0
$$

"Hence, MU is not a theorem of the MIU-system." No amount of playing inside the rules shows this.
You have to step outside and reason _about_ them.

## A sentence about itself

Gödel made arithmetic step outside on its own. He gave every formula and proof a code number,
so "this formula has a proof" becomes a statement about numbers. Then he built a sentence $G$:
"We are therefore confronted with a proposition which asserts its own unprovability"
([Gödel 1931, Meltzer translation, pp. 40–41](https://monoskop.org/images/9/93/Kurt_G%C3%B6del_On_Formally_Undecidable_Propositions_of_Principia_Mathematica_and_Related_Systems_1992.pdf)):

$$
G \;\leftrightarrow\; \neg\,\mathrm{Prov}(\ulcorner G \urcorner)
$$

The trick that builds it is a diagonal, the same one Cantor used in 1891 and Turing in 1936 for
the [halting problem](/articles/how-hard-is-hard/halting).

<div class="fx-figure">
  <OneDiagonal client:visible />
</div>

If the system is consistent it cannot prove $G$, which is exactly what $G$ says, so $G$ is true. Unprovable here always means unprovable _in that system_: add $G$ as a new axiom and the
bigger system has a new $G$ of its own. (Gödel's proof needed a slightly stronger assumption,
ω-consistency. J. B. Rosser got by with plain consistency in 1936.) The second theorem follows: if
such a system is consistent, it cannot prove that it is.

## Turing's shortcut

Turing saw that a complete system would hand us a halting decider. A machine 𝒦 that writes out
every proof in turn settles any formula 𝔄: "Sooner or later 𝒦 will reach either 𝔄 or −𝔄"
([Turing 1936, §11, p. 259](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)).

<div class="fx-figure">
  <ProofSearch client:visible />
</div>

If every "P halts" or "P never halts" had a proof, this machine would solve the halting problem.
It can't, so some program that never halts has no proof that it never halts. This needs one
assumption: the system only proves true things about halting.

Next, [harder than NP](/articles/how-hard-is-hard/beyond-np): problems that can be solved, but
only with enormous time or memory.

<Lesson>

A consistent system strong enough for arithmetic has true statements it cannot prove, and it
cannot prove its own consistency.

</Lesson>
