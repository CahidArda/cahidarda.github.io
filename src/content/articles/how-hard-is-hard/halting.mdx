An app freezes and the wheel keeps spinning. Is it stuck for good, or one second from done? It
would be nice if the computer could just check. It can't, and not because nobody has written that
check yet. In 1936 Alan Turing proved that no program can
decide, for every program and input, whether it will ever stop. This is the **halting problem**,
the first question shown to have no algorithm at all.

## The contrarian

Suppose someone hands you $H$, a perfect predictor. Give it any program and any input and it
answers "halts" or "loops". A program is just text, so you can even feed a program its own code
as its input. Now write a short program $D$. Give it any program $x$, and $D$ asks $H$ one
question: "what does $x$ do when it is fed its own code?" Then $D$ does the opposite of the answer:

$$
D(x) = \begin{cases} \text{loop forever} & \text{if } H \text{ says } x(x) \text{ halts} \\ \text{halt} & \text{if } H \text{ says } x(x) \text{ loops} \end{cases}
$$

Run $D$ on its own code. Whatever $H$ predicts, $D$ does the other thing, so no $H$ exists.
Turing put it as "there can be no machine ℰ which, when supplied with the S.D of an arbitrary
machine ℳ, will determine whether ℳ ever prints a given symbol"
([Turing, 1936, p. 248](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)). The name
"halting problem" came later; Sipser gives the modern proof (3rd ed., section 4.2).

## Why not just run it?

Running a program tells you it halts once it halts. Until then, you know nothing:

```python
while n != 1:
    if n % 2 == 0:
        n = n // 2
    else:
        n = 3 * n + 1
```

Does it stop for every starting $n$? That is the Collatz conjecture. Computers have checked every
start below $2^{71}$
([Barina, 2025](https://www.fit.vut.cz/research/result-file/c197809/298514/s11227-025-07337-0.pdf)),
and nobody has a proof.

## No perfect bug finder

The same trick breaks any tool that promises to answer a question about what every program
_does_: will it crash, is it a virus. This is Rice's theorem (Rice, 1953; Sipser, chapter 5). Real
checkers survive by sometimes answering "not sure".

## Where the trouble starts

Douglas Hofstadter draws the line with two toy languages in _Gödel, Escher, Bach_ (1979,
chapter XIII). In BlooP every loop gets a bound before it starts, so every program halts; BlooP
computes exactly the primitive recursive functions. FlooP adds loops with no bound, which "can
carry out unpredictable or even infinite searches". That one change is where undecidability
enters: FlooP can do whatever a computer can, halting problem included. A still stronger GlooP,
he concludes, is "a myth" if we accept the Church-Turing thesis. Unbounded search also leads to
[true statements that cannot be proved](/articles/how-hard-is-hard/unprovable).

Problems in [P vs NP](/articles/how-hard-is-hard/p-vs-np) are slow. This one is impossible, and
it sits outside every class on the [map of harder problems](/articles/how-hard-is-hard/beyond-np).

Some questions have no algorithm at all. No program can predict, for every program, whether it
